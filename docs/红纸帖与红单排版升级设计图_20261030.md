## 一、现状诊断（承接立项书）

| # | 现状 | 问题 |
|---|---|---|
| 1 | 全部段落 `justify=CENTER`，字号 24/18/16/15 四级 | 全居中导致长信息块（干支、吉时、冲煞）无法对齐扫读；层级差仅 2pt，视觉上"齐平一片" |
| 2 | 信息以"词条＋空格"散行排布（`干　支：…`、`冲：…　煞：…`） | 无表格骨架，读者无法纵向比对；打印后易错行 |
| 3 | 评分行 `评　分：256分　★★★★★` 与正文同字号 | 核心结论（吉/不吉、星级）不突出，与"注意事项"同权重 |
| 4 | 否决原因只有 `⚠ {原因}` 文本行 | 红纸帖（HTML/Text 渲染）无 §203 详情窗那套 `veto_highlight` 底色块；"不吉"与"吉"版式几乎同构，仅标题字不同 |
| 5 | 吉日软降级（受死日/红纱日/冲新娘等）仅安葬模板有动态【重要避忌】段 | 嫁娶/修造/入宅等吉日帖**看不到降级提示**，用户在纸上拿不到风险信息 |
| 6 | 三吉时为三行等权 `发轿：…` `迎娶：…` `拜堂：…` | 无时间轴/无阶段视觉引导，"发轿"这个最关键的时点被淹没 |
| 7 | 无边框、无印章、无双线分隔；`sep` 仅一条细线 | 传统红帖的"仪式感/权威感"缺失 |
| 8 | 落款（择日师/依据/岁次）与正文同层级 | 权威背书不显 |

## 二、设计原则（四条）

1. **一页一结论**：读者 3 秒内必须看到「吉／不吉」大字与星级；其余为支撑信息。
2. **表格承载事实，文字承载判断**：日期、干支、事主、坐向、吉时一律入表；断语、注意事项出表。
3. **风险必须自带视觉重量**：否决原因 / 避煞方位 / 冲煞 走"警示块"，与正文物理隔离（底色 + 边框），绝不与吉语同排。
4. **吉凶两版式彻底分家**：吉日帖＝明黄/朱红/墨黑三色；否决帖＝深红底 + 明黄"不吉"牌，结构上不允许出现"大利/大吉"字样（沿用 §198 P1-1 红线）。

## 四、视觉规格（可直接落地的数值）

### 4.1 色彩

| 用途 | 色值 | 说明 |
|---|---|---|
| 吉帖纸底 | `#C11B17`（沿用 `RED_PAPER`） | 传统朱红，打印偏深，建议打印版降到 `#D32F2F` 提高墨色对比 |
| 否决帖纸底 | `#8B0000` | 深红，明度低于吉帖，远看即知"不吉" |
| 正文墨色 | `#1A1A1A` | 沿用 |
| 金色描边/分隔 | `#C9A227` | 新增，用于双线框、云纹分隔、印章边框 |
| 警示块底 | `#FFF3B0` | 明黄，红底上唯一高亮载体 |
| 警示块竖条/字 | `#B22222`（文字）＋ `#8B0000`（4pt 竖条） | 与 §203 `veto_highlight` 同色系，保持软件内一致性 |
| 否决牌 | 底 `#FFD400` / 字 `#1A1A1A` | 最高对比，打印最稳 |

### 4.2 字号阶梯（现四级 24/18/16/15 → 新七级）

| 新 tag | 字号 | 字体 | 用途 |
|---|---|---|---|
| `verdict` | 36pt bold | 楷体 | 吉/不吉大字（**新增**） |
| `title` | 26pt bold | 楷体 | 主标题（+2） |
| `stamp` | 20pt bold | 隶书/楷体 | 朱印、否决牌（**新增**） |
| `h2` | 18pt bold | 楷体 | 分区标题（保持） |
| `body` | 16pt | 楷体 | 正文（保持） |
| `tbl` | 15pt | 楷体 | 表格单元格（**新增**，左对齐） |
| `small` | 13pt | 楷体 | 落款、依据（−2，弱化） |

### 4.3 间距与对齐

- 页面留白：A4 四边 10mm（现 8mm 偏挤，双线框需让位）。
- 分区之间：`8mm` 空行 + 一条云纹分隔（`sep`）。
- 表格：两列，列宽 22% / 78%，行高统一 9mm，列间 0.6pt 金线；单元格**左对齐**（现全居中）。
- 吉时区：左侧 3mm 时间轴竖线（金），节点为空心圆；三行等距 10mm。

## 五、Tag 体系扩展（实现映射）

现有：`title / sub / h2 / body / small / dia / sep / warnhl`（[`_TAG_CLASS` L1303](file:///d:/自编择日软件/专业级正五行择日软件/modules/择日贴.py#L1303-L1304)）

建议新增 5 个 tag（**纯加法，不改既有 tag 语义，向后兼容**）：

| 新 tag | 行元组形态 | HTML class | tkinter 样式 | 用途 |
|---|---|---|---|---|
| `verdict` | `('verdict', '★ ★ ★ ★ ★　上　吉')` | `.verdict{font:36pt bold;text-align:center}` | 36pt bold + 字距 6px | 结论大字 |
| `stamp` | `('stamp', '本 日 不 吉')` | `.stamp{display:inline-block;background:#FFD400;padding:6mm}` | 20pt bold + 明黄底 | 否决牌/朱印 |
| `tbl` | `('tbl', '公历│2026年03月20日', '农历│二月初二')` | `<table>` 两列 | 15pt + `justify=LEFT` | 信息表行（首元素为行键） |
| `warn` | `('warn', '注意事项：本日为受死日…')` | `.warn{border-left:4pt solid #8B0000;background:#FFF3B0}` | 16pt + 黄底 + 左边距 | 警示块 |
| `framebegin/frameend` | 标记行 | `.paper` 双线框 | 段落边框模拟 | 页框（打印走 CSS，GUI 走 Text border） |

## 七、发轿单（红单）专项设计

现状：无独立发轿单，发轿时辰是嫁娶帖三吉时之一（[`L469`](file:///d:/自编择日软件/专业级正五行择日软件/modules/择日贴.py#L469)）。

建议**不新增单据类型**（避免单据膨胀），改为在嫁娶帖内做"发轿时间轴"强化：

```
【迎 娶 时 辰】
  ① 发 轿  壬辰时 07:00-09:00  大吉  ← 加粗+朱圈（最高权重）
  ② 迎 娶  癸巳时 09:00-11:00  吉
  ③ 拜 堂  甲午时 15:00-17:00  吉
  附：新娘出阁方向宜向 东南（喜神方）              ← 若后续接入方位模块
```

若日后确需独立"发轿单"（如给轿夫手持），再单独立项：A5 半页、单列、只留 发轿时刻 + 出阁方向 + 忌冲生肖。

## 九、风险与不做的事

- **不改分值与判定**：本设计只动展示层，任何 `评分器`/`规则`/`神煞` 逻辑零改动。
- **不改否决红线**：否决帖仍禁止出现"大利/大吉/日吉时良"（§198 P1-1）。
- **不引入外部字体依赖**：仅用系统楷体/隶书回退链，避免打包缺字。
- **打印优先**：所有色值以"黑白打印机可辨"为底线（警示块靠底色灰度 + 左边框，而非纯色彩区分）。
- **暂不做**：动态纹样/图片背景（打印成本与兼容风险高）；独立发轿单（先看嫁娶帖时间轴效果）。

## 十、验收标准（设计达标线）

1. 3 秒识别：任意一页，第一眼能看到吉/不吉结论（36pt 以上，占页宽 ≥ 60%）。
2. 零歧义：否决页不出现任何吉语；吉页必含警示区（即使无风险也印"本日无重大避忌"）。
3. 表格可扫读：公历/农历/干支/用事/事主/坐向 六项纵向对齐，列宽一致。
4. 降级可见：受死日/红纱日/冲新娘等软忌在吉页以 `warn` 块呈现，不再只存在于详情窗口。
5. 打印稳定：A4 竖版单页不溢页（嫁娶/修造/入宅/安葬四类最长模板须实测）。
