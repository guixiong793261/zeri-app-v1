## 三、动作时序模型

### 3.1 动作序列（配置化，禁止硬编码进判断逻辑）

```python
# modules/事项标准.py（新增，纯配置；不改 UI_EVENTS）
ACTION_SEQUENCES = {
    '嫁娶': [
        {'seq': 1, 'key': 'fa_jiao', 'label': '起轿·发轿'},
        {'seq': 2, 'key': 'ying_qu', 'label': '迎娶·进门'},
        {'seq': 3, 'key': 'jiao_bai', 'label': '交拜·合卺'},
    ],
    # 订婚/入宅/安葬等按各自 _STAGE_LABELS 另行增补（P2-B 之后，不随本批）
}
```

- 标签与红帖 `_STAGE_LABELS['marriage']` 必须逐字一致（单一文案源：本表为准，
  择日贴改为引用，避免两处漂移）。
- 未配置的事项 → 动作轴**整块不显示**，红帖行为完全不变（向后兼容）。

### 3.2 候选池与筛选规则

候选池 = 该日 `hour_records` 12 项（已含 `score/level/veto/disabled/shashi`）。

| 规则 | 内容 |
|---|---|
| R1 硬排除 | `disabled=True`、`veto>0`、`score<=0`、`shashi=True`（杀师时） |
| R2 冲命校验 | 以 `get_lucky_hours` 的 `禁用` 为唯一判定源；plan 层再做一次**独立自算**（年支+6）仅作交叉校验，不一致 → 记 `warn` 并在 UI 显示（不静默） |
| R3 时序单调 | 按**钟点起点**排序，不按地支序（子时 23:00 应排最后，见 D2）：`子=23 > 戌=19 …`；三段必须严格递增 |
| R4 一辰一动作 | 同一时辰不得分配给两个动作（无典据支持同辰两礼，且易生歧义） |
| R5 间隔 | **不设硬间隔**（三库无明文），仅提示"相邻两礼同一步时辰过近"，由择日师自行调整 |

### 3.3 选优算法（纯函数，无 GUI、无 IO）

```
plan_actions(hours, owners, actions) -> {
    'plan':    [{'seq','label','zhi','ganzhi','range','score','level','grade','tags'}],
    'status':  'full' | 'partial' | 'insufficient' | 'none',
    'missing': ['起轿·发轿'],          # 缺哪几段
    'checks':  [{'name':'cross_check','ok':True,'detail':...}],
    'score':   sum,                     # 仅用于同日多方案比较，不进日课总分
}
```

- 穷举 12 选 3 的递增组合（C(12,3)=220，含 2 段/1 段情形 <300 次），
  按 `(段数, Σscore)` 取最优；同分取**更早钟点**（民俗发轿宜早）。
- 复杂度可忽略（单日 <1ms），不影响反推 30 天耗时（现 2.9~6.6s）。

### 3.4 状态分级

| status | 含义 | UI 表现 |
|---|---|---|
| `full` | 3 段齐备 | 动作轴三行 + 绿标 |
| `partial` | 仅 2 段可用 | 动作轴两行 + 黄标「缺 X 吉时」 |
| `insufficient` | 仅 1 段 | 动作轴一行 + 橙标「本日不足三段，建议另择」 |
| `none` | 0 段 | 动作轴空白 + 红标「本日无可用动作时辰」 |

## 四、降权与警示（用户问 3 的处置）

**建议方案 B（Top-N 内显式降权 + 原因列写明），不采用"直接剔除出榜"**：

1. 降权实现：`rank_day` 前插入一档 `action_tier`（full=0 / partial=1 /
   insufficient=2 / none=3），**仅对 `ACTION_SEQUENCES` 内事项生效**，
   且**不改分值、不改收录层**（吉日仍是吉日，只是同层内排序后移）。
2. 原因列追加：`缺上轿吉时（仅 2 段可用）`，与既有「扣分主因」同列拼接。
3. **绝不剔除**：剔出榜会让用户以为软件"没算到"，反而引发不信任；
   且祥日挑时辰本就是择日师的活，软件只做"可行性预警"。
4. 若某日 `score` 极高但 `status=none`，Top-N 行标 ★ 的分量不变，
   但排序自然下沉——用于"高分日未必可用"的真实提醒。

> **拍板项 Q3**：`rank_day` 追加 `action_tier` 会改变 Top-N 顺序，
> 需重冻 `tests/verify_210_search_top_n.py` 基线。若你要求"零顺序漂移"，
> 则改为**只标记不排序**（榜单顺序完全不变，仅加黄标与提示）。

### 5.3 红帖侧最小改动（三处，均为加法）

1. `prepare_entry`：若 `entry['action_plan']` 存在 → `_jishi` 直接按 plan 生成
   （`manual=True, from_plan=True`），**跳过**自动前三筛选；仍执行 R2 交叉校验，
   冲突则**拒绝生成并弹窗说明**（绝不把冲命时辰印成吉时）。
2. `compose_marriage_lines`：`status != full` 时在吉时区追加 `warn` 行
   `⚠ 本日吉时不足：缺「起轿·发轿」，请另择或调整行程`（tag 已注册，纯展示）。
3. 打印模板：吉时区改用可选 `rule` + 竖排编号（"三层四区"设计图 §4.3 时间轴竖线），
   属 **S5 增量**，可选做，不影响功能。

### 5.4 与「三层四区」的对接位置

- 动作轴 = 设计图「〔吉时区〕」三行，已有 ①②③ 圈码（`_stage_jishi_line`）。
- 缺段警示 = 「〔警示区〕」`warn` 块（与受死日降级警示同区，不混入吉时区）。
- 结论区（`verdict` 大字）**不动**：动作轴不参与日课评级，避免"假精度"。

## 七、现存缺陷清单（须先拍板处置口径）
