### 2.2 三条典型链路的具体数据流

**（a）嫁娶：`shensha_list` 与总分彻底分家**

```
get_checker()  ✗ 未调用
婚嫁算法 details ──► total_score = marriage.score + 喜用 + 月令 + 太阳太阴   (1039)
                      ▲ 不含 shensha_list、不含规则 yi/ji、不含三煞

局部 shensha_list ──► 只进 result['shensha_list']（1364），供【神煞信息】渲染
   ├ 大利月 +30（1245-1255）──► 与婚嫁算法 details 的利月项同源叠加，但总分只认 details 那份
   ├ 羊刃 -15/-25（1260-1262）──► 与 details 羊刃项同源，总分只认 details 那份
   └ 福星 +10（1264-1268）────► details 无对应项 → 永远不计分
```

**（b）通用：五行评分是「容器」，`shensha_list` 是「填料」**

```
get_checker()/修造扩展 ──► self.shensha_list ──► _build_wu_xing_breakdown (4901-4904)
                                                     │  神煞得分 = Σ score
                                                     ▼
                              wu_xing_result['score'] = 基础100 + 神煞 + ±宜忌 + 长生 + 地支 + 纳音
                                                     ▼
                              final_score = wx + 月令 + 喜用 + 相主 + 黄道 + 太阳 + 三煞 + 仙命坐山 (1938)
```
因此通用面的「0 分神煞」（D5/D6/D8/D9）在数理上确实是 0 贡献，展示与计分一致；**嫁娶面则是「列表与公式完全不相交」**，这是两种断点性质不同的地方。

**（c）修造：不是独立管线，是「换检查器 + 手抄表」**

### 3.2 「假低分」的四条成因链

1. **基线错位（最大项）**：通用 100 起评、婚嫁 60 起评（T1 前置），但等级阈值只有一套（T8）。60 分在通用面是「❌ 凶」下沿，在婚嫁面却是「★★ 中吉」的原料（婚嫁 60 基础 + 利月 30 + 天德 20 ≈ 110 → ★★★ 吉）。
2. **降级项累积压穿线**：三煞日/时柱、D2 作灶、月份不宜等「扣分不否决」项把五行分从 30+ 压到 29，触发 T4；T7 的回退逻辑（1704-1748）再把它救回——于是同一天在不同月份/不同开关下可能「否决 ↔ 可用」翻转。
3. **飞星加权封顶**：T3 的 `min(100)` 让高分局在 feixing 模式下被硬压到 100，而 pure 模式不封顶——同一日课切换「界面默认 pure / 引擎默认 feixing」即分数不同（[评分器.py:736-739](file:///d:/自编择日软件/专业级正五行择日软件/modules/评分器.py#L736-L739)）。
4. **级分分离的三处特赦**：T10（仙命）、T11/T12（婚嫁）、T9（五行底线）都是「只改级不改分」。报告顶部的分数与等级因此不满足单一函数关系，用户读作「分低却能用的假低分」。
