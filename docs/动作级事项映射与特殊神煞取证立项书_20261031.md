## 二、待解问题（四类）

### 2.1 动作 → 事项映射

| 方案 | 内容 | 风险 |
|---|---|---|
| M1 复用嫁娶 | 三动作全部映射 `嫁娶`，仅用时辰窗区分 | 三动作同分＝假精度（预研 R1） |
| M2 复用嫁娶＋动作约束 | 分值仍取嫁娶，但按动作加"时辰窗 + 相邻约束 + 动作专属吉神/凶煞" | 需动作级神煞明文，否则是拍脑袋加权 |
| M3 独立口径 | 每个动作定义独立事项（新增 3 个 `UI_EVENTS`） | 影响 15 通道结构、键表、测试基线，成本最高 |

### 2.2 时辰窗（动作允许的时辰范围）

预研草案给出示例（发轿限卯～巳、拜堂限巳～未），但**示例不等于典据**。
需在三库中取证「发轿/迎娶/交拜」的时宜记载；无明文者只能作为
**民俗可配置项**，不得写死进评分。

### 2.3 相邻动作约束

- 时序：`h_i > h_{i-1}`（DP 硬约束）；
- 冲克：前动作时支与后动作时支六冲/相刑是否禁用（需典据或明确降级为提示）；
- 间隔：动作间最小时长（民俗默认 vs 可配置）。

### 2.4 特殊神煞取证清单（本立项的核心）

1. 「发轿 / 迎娶 / 交拜」三动作各自宜忌神煞：三库逐条核对，分五档判定；
2. 嫁娶通道现有 19 枚凶煞中，哪些属"日级"（可直接复用）、哪些有"时辰级"
   用法（可下沉动作级）、哪些纯属日级不得下沉；
3. 动作专属吉神（如"周堂"是否分动作、是否关时辰）；
4. 不得以民俗经验替代典据：**无证不放宽**，无明文项只能以"提示/可配置"形态存在。
