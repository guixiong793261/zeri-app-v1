## 6.0 裁决的方法论

### 6.0.1 三库主锚与取证纪律

| 层级 | 典籍 | 角色 | 语料规模 |
| --- | --- | --- | --- |
| 主锚 | 《协纪辨方书》 | 官方钦定，判伪效力最高 | 286,084 字 |
| 互校 | 《御定星历考原》 | 与协纪互证，反向不支持即降档 | 71,554 字 |
| 第三参照 | 《陈子性藏书》 | 民间实操参照，单条记载不单独成立 | 740,117 字 |

**四条取证纪律**（B6 全部裁决共同遵守）：

1. **全卷逐字扫描，不抽样**。检索词含繁简/异体近似，命中后逐条人工核读。
2. **伪共现排除**。关键词命中不等于语义命中，必须读上下文；「方道」78 处全为修方，就不能算作出行依据。
3. **无证据不放宽**。三库无载 → 不得新增规则、不得升否决、不得「凭经验补一条」。
4. **穷尽性证明**。每份取证报告必须列出「检索过但无记载」的清单，证明不是没查到，而是确实没有。

### 6.0.2 判伪的效力顺序

```
协纪卷三十六「辨讹」钦定判伪  ＞  协纪正文无载  ＞  考原反向不支持  ＞  陈书单条孤证  ＞  坊刻通书流传
```

- **钦定判伪**：直接删除，永不复用（吉庆、杨公忌）。
- **主锚无载**：降为待证隔离或删除（杀师日、十恶大败、日课岁破）。
- **考原反向**：降档、收窄事项，不升否决（日游方出行）。
- **陈书孤证**：可作第三参照，但不得对抗主锚（红嘴朱雀是「陈书有载 + 主锚无载」的**唯一保留特例**，理由见 6.9）。
- **坊刻流传**：只作「提示性轻扣」，绝不升格为否决（红纱日）。

### 6.0.3 本册的证伪结构

每条铁案都必须回答三个问题：

| 问题 | 若答不上来 |
| --- | --- |
| 这条规则**典出何处**（卷次/页）？ | 只能挂「待证」，不能计分 |
| 它的**适用域**是什么（日辰 / 方位 / 年神 / 时辰）？ | 极可能重犯「方位神误作日辰神」 |
| 它的**力度**有明文吗？ | 只能取下限轻扣，不能否决 |

## 6.1 论杀师日之伪

### 6.1.1 命题

**「杀师日」不是典据神煞，而是两套互相矛盾的口诀拼接物；它不配拥有 -30 的重扣，更不配否决。**

### 6.1.2 典据核查

| 库 | 检索结果 | 说明 |
| --- | --- | --- |
| 协纪 | **零卷页命中** | 无「杀师」条目、无按语、无辨讹 |
| 考原 | **零命中** | 同上 |
| 陈书 | **零命中** | 同上 |

仓库内唯一「依据」是一份**二手对照表**，而对照表所记口诀本身就有两套：

| 口诀 | 内容 | 问题 |
| --- | --- | --- |
| 算法 1 | 春戌、夏丑、秋辰、冬未 | **实为「四击 / 死别」表**，因跨家族污染已废弃 |
| 算法 2 | 年支 → 杀师月 → 日支 | 转换链无任何明文，属自造 |
| 对照表 | 春卯、夏午、秋酉、冬子 | 被协纪辨讹点名「通书误作大败日」 |

**三代口诀，三种答案，无一有典。** 这不是「流派差异」，是**没有源头**。

### 6.1.3 软件处置

| 动作 | 状态 |
| --- | --- |
| 升 HARD_VETO | **拒绝**（无证据不放宽） |
| 计分 | 降为 **0 分，仅识别展示** |
| 登记 | `DISPLAY_ONLY_REGISTRY['杀师日'] = {'source': 'pending_canon'}` |
| 文案 | 「待证隔离：三库零载且现行口诀系四击/死别误植，仅识别展示不计分」 |
| 嫁娶通道 | 整链撤出（与杀师时同批） |

由 `_add_shensha` 统一查表：命中 `display_only_info` → `score = 0` 并追加待证注（见 [神煞基类.py](file:///d:/自编择日软件/专业级正五行择日软件/modules/shensha/神煞基类.py#L2032-L2040)）。

### 6.1.4 反断言

```python
# 任何通道、任何日期，杀师日的 contributed 必须为 0
assert all(a['contributed'] == 0 for a in audit if a['name'] == '杀师日')
# 任何报告不得出现「杀师日一票否决」
assert '杀师日' not in veto_reasons
```

### 6.1.5 残留（诚实记账）

- **杀师时**（时柱戊午）与杀师日同源，但尚未同批隔离，修造/动土仍按 -30 发射。**挂账**：要么按同一判据隔离，要么补出典据；不得默认它「已经删了」。
- 二手对照表仍在仓库内，**不删除**（作为反证材料留档），但不得被任何代码引用。

> **铁案一句话**：没有典据的口诀，最多只能「提示」，不能「定罪」。

## 6.2 论红纱日之降格（不是撤销，是降格）

### 6.2.1 命题

**红纱日有典可查、有明确起例，但主锚奏疏判其「甚属无当」；因此它不能否决，也不应在嫁娶通道继续计分——但作为通书长期流传的民俗提示，在修造/安床/通用保留 -15 轻扣。**

### 6.2.2 典据

> **协纪 p279217（奏疏）**：红纱日「**甚属无当**」，「**应请一并删去**」。

- 起例（辨讹正解）：**四孟月巳、四仲月酉、四季月丑**（孟巳、仲酉，旧表曾对调）。
- 月界：**节气月建**，闰月不另立。
- 陈书注「历不忌」，与协纪奏疏同向。

### 6.2.3 软件处置

| 通道 | 处置 | 分 |
| --- | --- | --- |
| 嫁娶 | **整链撤出**（§197 D6-Q1 / §212 拍板 1） | 0（不再计分） |
| 修造 / 安床 / 通用 | 保留 | **-15**（轻扣，非否决） |
| 注册键 `('嫁娶','红纱日') = -20` | 成为全年 0 发射的**死键** | 登记 BACKLOG G-1，**禁止顺手删** |

> **为什么不直接全删**：协纪判的是「此忌无当」，不是「此日不存在」。通书流传数百年，择日师与客户都认这个名字；保留 -15 是「提示性降格」，删掉反而让报告与民间认知脱节。这与「吉庆」不同——吉庆是钦定**伪吉日**，留着头。

### 6.2.4 反断言

```python
# 2026-01-15（红纱日）嫁娶通道：不否决、不扣红纱分
assert marriage_score(2026, 1, 15) == baseline_without_hongsha
assert '红纱日' not in marriage_veto_reasons
# 修造同日仍应有 -15
assert shensha_score('修造', '红纱日') == -15
```

### 6.2.5 残留

- 「红砂日 / 红纱日」双名曾同日双扣（2026-01-15 实测 -20 + -20）。§193 已统一正名为**红纱日**，`_SHENSHA_ALIAS_KEY` 归一生效，此坑已封。

> **铁案一句话**：判「无当」不等于判「不存在」；降格比删除更接近典意。

## 6.3 论杨公忌与三娘煞之伪

### 6.3.1 命题

**杨公忌、真三娘煞属「术士之揑造」，主锚辨讹已判伪；嫁娶通道必须撤出，其他通道最多保留提示性轻扣。**

### 6.3.2 典据

> **协纪卷三十六·辨讹（xj/279254）**：「**杨公忌**：世俗多畏杨公忌，通书亦多载之……」——判为世俗讹传。

> 协纪辨讹对「三娘煞」同判术士捏造（与杨公忌同类）。

- 考原：**零命中**。
- 陈书：**零命中**。

### 6.3.3 软件处置

| 神煞 | 嫁娶 | 修造/安床等 |
| --- | --- | --- |
| 杨公忌日 | 撤出（§212） | 保留 -20/-10 轻扣 |
| 真三娘煞 | 撤出（§212） | 保留 -15 轻扣 |

> **为什么不全删**：与红纱同理——民间影响深，全删会让报告「看起来不专业」。但**绝不能否决**，也**绝不能进 HARD_VETO 关键词表**。

### 6.3.4 反断言

```python

assert not is_vetoed(2026, 5, 23, '嫁娶')

assert all(name not in PSEUDO_FOR_MARRIAGE for name in emitted_marriage_list)
```

> **铁案一句话**：钦定判伪的神煞，可以「提示」，不能「裁决」。

## 6.4 论十恶大败之删

### 6.4.1 命题

**十恶大败是「本命避忌」，不是「日课普适忌日」；把它注册为全事项忌日，是典型的领域错配。**

### 6.4.2 典据

> **协纪**：「**惟随各年及本命避之**」。

- 语义：十恶大败按**年**与**本命**避，不按日课逐日判。
- 三库均无「日课普适忌十恶大败」明文。

### 6.4.3 软件处置

- 日课普适注册**全删**（谓词 + 发射 + 注册行）。
- 不作任何「提示性保留」——它不是民俗问题，是**领域错误**。

### 6.4.4 反断言

```python
assert shensha_score('*', '十恶大败') is None   # 注册已不存在
assert '十恶大败' not in any_channel_shensha_names()
```

> **铁案一句话**：年神、本命神、日辰神、方位神，四域不可混装。

## 6.5 论岁破 / 太岁之日课误用

### 6.5.1 命题

**岁破、太岁是「方位神」，不是「日辰神」。协纪卷四按语已明判「历家特误以年方配日辰耳」。**

### 6.5.2 典据

> **协纪卷四按语**：「**历家特误以年方配日辰耳**」。

- 岁破 = 太岁所冲之**方**；太岁 = 岁君所在之**方**。二者皆论方，不论日。
- 日课四柱中「年支冲日支」是另一回事（那是日课内部的地支关系），不能叫「岁破日」。

### 6.5.3 软件处置

| 项 | 处置 |
| --- | --- |
| 日课普适「岁破」注册 | 删除（001 §140） |
| 太岁（日辰）动土/拆舍发射 + 2 键 | 删除，谓词保留备用 |
| 山家「岁破方 / 年冲山」 | **保留**（这才是方位义） |
| 出行「岁破方」 | 不纳入（三库出行语境 0 处） |

### 6.5.4 反断言

```python
# 日课不得因「年支冲日支」被冠以岁破并否决
assert '岁破' not in day_level_veto_reasons
# 山家仍必须有年冲山封禁
assert '年冲山' in mountain_block_reasons(2026, some_date, shan='子')
```

> **铁案一句话**：同一个词，换了域就是另一个神；「岁破」在山是煞，在日是伪。

## 6.7 论福星旧法之误

### 6.7.1 命题

**旧「福星」谓词（年支 +6 冲位查日支）与最凶神「岁破」完全同构，导致岁破日白送 +10 吉分。这是算法层的自相矛盾，必须换派重立。**

### 6.7.2 证据链

| 环节 | 事实 |
| --- | --- |
| 旧谓词 | 年支顺数 6 位（即冲位）查日支 → 命中即「福星」 |
| 岁破谓词 | 年支冲位（+6）查日支 → 命中即「岁破」 |
| 结果 | **同一天，既岁破又福星** |
| 实测 | 2026 年 31 天次 / 事件，岁破日白送 +10 |

**一个谓词不可能同时定义「最凶」和「最吉」。** 这不是巧合，是抄错了表。

### 6.7.3 正派

> **协纪卷七·义例五**：「**日干生时干曰福星贵人**」（食神派）。
> 陈书附录《福星诀》同派互证。

- 只查**时柱**，不查日支。
- `日干生时干`：日干五行生时干五行。
- 14 条通道键按正统加回。

### 6.7.4 软件处置

- 发射侧：旧谓词整链删除，`_build_fuxing_shensha` 按**时辰派**重建。
- 展示侧：同步修正，不再显示「年支冲位」的伪福星。
- 岁破交叉敞口：随重建自动消失（两者不再同构）。

### 6.7.5 反断言

```python
# 岁破日不得有福星
assert not has_fuxing(veto_day_2026)
# 福星只由时柱决定：同日不同时辰，福星状态可不同
assert fuxing(day, hour='甲') != fuxing(day, hour='乙')
```

> **铁案一句话**：吉神与凶神共用同一谓词，必有一错；错的那个，通常是抄表的人。

## 6.8 论大煞 / 飞廉 / 伏断 / 反支之收缩

### 6.8.1 命题

**这四族都「有典」，但典只给极窄的适用域；软件曾把它们扩成全事项凶煞，属超范围注册。处置是「收窄」，不是「删除」。**

### 6.8.2 逐项

| 神煞 | 典载适用域 | 旧实现 | 现处置 |
| --- | --- | --- | --- |
| **大煞** | 协纪仅忌**军事** | 注册为多事项凶煞 | 超范围注册删除 |
| **飞廉** | 卷三：「在岁名飞廉，在月名大煞」——**名/域错配** | 作日辰神发射计分 | 日辰发射与计分全撤，谓词保留 |
| **伏断** | 辨讹：「**伏断本选时之法**」；卷十无条目、卷十一 0 命中 | 作日家神煞发射 | 日家发射全删，谓词保留（选时层） |
| **反支** | 卷十仅忌**帝王用事** | 全事项发射 + 13 键 | 全删发射与键，谓词保留 |

### 6.8.3 为什么「保留谓词」

收窄不等于遗忘。谓词留在代码里，是给未来「选时层」「帝王用事层」留接口；**键与发射删掉，是为了不让它在当前事项层继续误伤**。

### 6.8.4 反断言

```python
assert '大煞' not in general_channel_scores          # 超范围已删
assert feilian_day_emission == []                    # 飞廉日辰零发射
assert fuduan_day_emission == []                     # 伏断日家零发射
assert '反支' not in any_channel_keys                # 反支 13 键已删
```

> **铁案一句话**：收窄是「把神放回它的域」，不是「把这个神删掉」。

## 6.9 论红嘴朱雀之降维（唯一保留的陈书孤证）

### 6.9.1 命题

**红嘴朱雀在协纪、考原均无载，仅陈书有九宫起例与一句实操禁令。按「陈书孤证不得对抗主锚」的通则，本应删除；但它被保留并升为入宅 HARD_VETO，理由是「主锚无载 ≠ 主锚反对」，且陈书给出了可执行的九宫定位法与明确后果描述。**

这是全书中**唯一**一次「孤证保留」，必须写清边界，否则会被当成双标。

### 6.9.2 典据

> **陈书 p96**：「**切不可犯紅嘴朱雀入中宮**」，犯者不吉、屢見甚驗。
> 九宫起例见陈书 p890。

- 协纪：无「红嘴朱雀」条目。
- 考原：无。
- 陈书：**有起例、有方位（中宫/震宫）、有效验描述**，但**无分值力度原文**。

### 6.9.3 为什么可以保留

| 条件 | 红嘴朱雀是否满足 |
| --- | --- |
| 第三参照有明确起例 | ✅ 九宫起例 p890 |
| 有明确禁忌对象 | ✅ 入中宫 → 忌入宅、归火 |
| 有后果描述 | ✅ 「犯者不吉、屢見甚驗」 |
| 主锚是否**反对** | ❌ 无反对，仅无载 |
| 是否被用来**放宽** | ❌ 是加严，不是放宽 |

> 关键在最后一条：「无证据不放宽」约束的是**放宽**；对「加严」的孤证，只要起例可执行、后果有描述，可以作为**第三参照的保守条款**保留，但必须标注「典据单一」。

### 6.9.4 软件处置

| 通道 | 处置 | 分值 |
| --- | --- | --- |
| **入宅** | ⛔ **HARD_VETO** | 按典 -30（拒绝 -12 弱化档） |
| 作灶（震宫） | 重度扣分 | -30 |
| 安床 | **方位门控**（仅当红嘴朱雀落宫与安床方位相干才触发） | -30 |
| 嫁娶 | 仅展示 | 0（一票否决另由时辰级白虎/朱雀处理） |

> 入宅硬门槛见 [评分器.py](file:///d:/自编择日软件/专业级正五行择日软件/modules/评分器.py#L2630-L2700)。
> 分值取 -30 而非 -12：陈书原文是「切不可犯」，语义强度对应最重档；-12 是旧「口舌是非」档，与「入中宫」不是同一件事。

### 6.9.5 反断言

```python

assert is_vetoed(2026, d, '入宅') for every 红嘴朱雀入中宫日
# 未入中宫（如仅到震宫）不得误触入宅否决
assert not is_vetoed(2026, d, '入宅') when 红嘴朱雀在震宫
```

### 6.9.6 边界声明

- 这是**唯一**的孤证保留案例。任何后来者想拿陈书单条再开一例，必须先回答：起例是否可执行？后果是否有描述？主锚是否反对？三者缺一，不得保留。
- 陈书 p96 的「入中宮」是**方位条件**，不是「见红嘴朱雀即凶」。忽略方位条件，就是把它又扩回了「全事项凶煞」。

> **铁案一句话**：孤证可以加严，不可以放宽；可以定点，不可以铺开。

## 6.10 论年三煞为何不判四柱

### 6.10.1 命题

**年三煞是「年神 + 方位」的复合煞，其威在「山向」，不在「日柱 / 时柱」。把年三煞铺到四柱，是方位神误作日辰神的又一次重犯。**

### 6.10.2 典据核查

| 检索 | 结果 |
| --- | --- |
| 协纪卷十一「年三煞」事目 | **70 事目 0 命中柱级** |
| 协纪「三煞」柱级忌 | 仅月/日三煞有柱级表述 |
| 考原 | 互校同向 |
| 陈书 | 无「年三煞犯日柱」条 |

> 协纪卷四按语的精神仍是同一句：「**历家特误以年方配日辰耳**」——年三煞本属年方，不是日辰。

### 6.10.3 软件处置（§211，2026-10-31）

| 层级 | 山向 | 向首 | 日柱 | 时柱 |
| --- | --- | --- | --- | --- |
| **年三煞** | -25 + ⛔ 否决 | -25 | **全面旁路（0）** | **全面旁路（0）** |
| 月三煞 | -20 | -20 | -20 | -15 |
| 日三煞 | -15 | -15 | — | -10 |

- 年三煞**只保留山向/向首**判定；四柱级（日柱、时柱）**整段跳过**，不是「降为 0 分」，而是**不进入计算**。
- 月日三煞保留柱级扣分（月三煞日柱 -20、时柱 -15；日三煞时柱 -10）。
- 月日三煞叠犯时柱另加 -15（防「两煞同柱只算一次」的漏扣）。

### 6.10.4 为什么要分年/月/日

| 煞 | 本体 | 应判对象 |
| --- | --- | --- |
| 年三煞 | 年支三合之冲 | **山向**（年方不可动） |
| 月三煞 | 月建三合之冲 | 山向 + 日柱 + 时柱（月内择日，柱级有意义） |
| 日三煞 | 日支三合之冲 | 山向 + 时柱（日内择时，时柱有意义） |

**级别越细，才越配柱级。** 年煞是一整年的方位禁令，拿它去否某一天的某个时辰，等于「用一年的地图找一天的厕所」。

### 6.10.5 反断言

```python
# 年三煞日柱：必须为 0，且不登记忌项
assert year_sansha_penalty(day_pillar) == 0
# 年三煞山向：必须保留否决
assert is_vetoed(shanzuo_in_year_sansha)
# 月三煞日柱仍然扣 20
assert month_sansha_penalty(day_pillar) == -20
```

> **铁案一句话**：年煞管方，月煞管日，日煞管时；越级执法，必生冤案。

## 6.11 论出行为何不看坐山看方向

### 6.11.1 命题

**出行没有「坐山」，只有「出发方向」。三库全卷中「出行坐山」零命中；把修造的山家封禁套到出行，是通道错配。**

### 6.11.2 取证结论（全卷逐字）

| 检索词 | 协纪 | 考原 | 陈书 | 判定 |
| --- | --- | --- | --- | --- |
| 出行方向 / 出方位 | 0 / 0 | 0 / 0 | 0 / 0 | 三库**无此术语** |
| 方道 | 20（**全为修方**） | 0 | 78（**全为修方**） | 出行语境 **0 处** |
| 岁破方 / 太岁方（作出行判据） | 1 / 2（均「必不可修」） | 0 / 0 | 0 / 0 | 出行语境 **0 处** |
| 出行三煞 / 坐山三煞 | 0 | 0 | 0 | **三库无载** |
| 天德方 / 月德方（出行） | 4 / 1（均修方制煞） | 0 | 2（天德含出行） | 仅陈书 1 条 |
| 鹤神 | 7（「出行忌抵向」，判俗信） | 0 | 1 | 仅 2 处，主锚降格 |
| 日游（出行） | 12（条目不含出行） | 6（只忌产室/扫舍/安床） | 1（忌日游方出行） | 考原**反向不支持** |
| 往亡 | 62 | 25 | 18 | 日忌 ✅ 三库一致 |

**穷尽性说明**：以上「0」为全卷逐字扫描（含繁简/异体近似），非抽样；未覆盖清代坊刻通书，结论不外推。

### 6.11.3 唯一可用的方向条文

> **陈书 p757**：「**元旦出行**：宜向天月二德天道及喜神所在之方出行吉；忌截路空亡时；**忌鹤神日游方，不宜从此方出行**。」

这是三库中**唯一**把「出行方向」写成可操作规则的条文，但：

- 场景限定「**元旦出行**」（岁首出行），不能推广为所有出行；
- 方向来源是通用吉方（天德/月德/天道/喜神）+ 忌方（鹤神/日游）；
- **无分值力度**，也无「出发地→目的地」的方位判定法。

### 6.11.4 软件处置（§201–§203）

| 项 | 处置 |
| --- | --- |
| 出行坐山 / 山家封禁（日冲山、岁破、五黄二黑） | **整段旁路**（§199/§201 切断） |
| 出行三煞 / 向方月破 / 分金 / 正体 | **全部取消**（原 20 课差 360 分） |
| 出行日忌（往亡、四离四绝、月厌、破日） | **保留**（三库一致） |
| 天德 / 月德 / 喜神方 | 新增轻权重 **+5 ~ +8**（取下限，不加岁德方） |
| 鹤神方 / 日游方 | 新增轻权重 **-5**（不否决） |
| 岁破方 / 太岁方 | **不纳入**（出行语境 0 处） |
| 方位叠合否决 | **不采纳**（无载） |
| UI 文案 | 「坐山」→「**出发方向**」，加「仅作参考」提示 |

### 6.11.5 反断言

```python
# 出行不得因坐山封禁被否
assert not is_vetoed(2026, d, '出行') for d in 日冲山日
# 出行三煞通道必须为 0
assert chuxing_sansha_penalty == 0
# 往亡仍然生效
assert shensha_score('出行', '往亡') == -15
# 方位不得单独构成否决
assert all(veto_reason != '出行方位' for veto_reason in veto_reasons)
```

> **铁案一句话**：出行的「山」是方向，不是坐山；方向只能加减分，不能定罪。

## 6.12 论重丧日不忌嫁娶

### 6.12.1 命题

**重丧是「丧葬凶事」的专忌，不是「吉事通忌」。陈书已明判：「重丧凶事，吉事俱忌者非」。**

### 6.12.2 典据

> **陈书 p54**：「**重丧凶事，吉事俱忌者非**」。

- 语义：重丧之忌，只应落在凶事（安葬）；把嫁娶、入宅、开业一并忌掉，是扩大解释。
- 协纪：重丧条在安葬语境，无「通忌吉事」明文。

### 6.12.3 软件处置（§212 C2）

| 通道 | 处置 |
| --- | --- |
| **安葬** | 保留：年重丧 / 三丧 / 复日 **⛔ HARD_VETO** |
| **嫁娶** | 撤出：从否决改为**可制化**（解禁） |
| 其他吉事 | 不发射重丧否决 |
| 起例 | 统一**墓库派**（重丧日起例归宗墓库派口径） |

### 6.12.4 反断言

```python
# 2026-01-15（重丧）嫁娶：不得否决
assert not is_vetoed(2026, 1, 15, '嫁娶')
# 同日安葬：必须否决
assert is_vetoed(2026, 1, 15, '安葬')
```

### 6.12.5 残留

- 重丧起例曾有「墓库派 / 三合派」两套，现已统一墓库派；旧表不得复活。
- 复日、三丧、年重丧三键的安葬否决权**保留**，不在本批撤销。

> **铁案一句话**：凶事的忌，不能借给吉事用；「俱忌」是扩大解释，不是典意。

## 6.13 论受死日之轻重

### 6.13.1 命题

**陈书对受死日只称「凶曜」，未给任何比较级；软件旧档 -22 无出处，应为 -15。入宅通道则因后果描述明确，升为 HARD_VETO。**

### 6.13.2 典据

- 陈书：受死日为「**凶曜**」——**无「大凶」「最凶」「不可犯」等比较级**。
- 协纪：有受死日条，未给分值。
- 旧档 -22：**无典据支撑**，属「看起来比 -20 更重一点」的自造档。

### 6.13.3 软件处置

| 项 | 旧 | 新 | 理由 |
| --- | --- | --- | --- |
| 通用扣分 | -22 | **-15** | 「凶曜」无比较级，取下限档 |
| 入宅 | 扣分 | **⛔ HARD_VETO**（0 分发射，否决另计） | 入宅后果描述明确 |
| 安葬 | 扣分 | 保留扣分（已有四大凶日硬否） | 不叠加升级 |
| 开业 | -22 | 撤出（注释保留） | 无开业专忌明文 |

> 实现上入宅/嫁娶发射 `0` 分条目（`_add_shensha('受死日', 0, '…一票否决，不计分')`），否决由硬门槛判定，避免「-15 扣分 + 否决」重复记账。

### 6.13.4 反断言

```python
assert shensha_score('*', '受死日') == -15          # 通用档
assert not any(score == -22 for score in all_scores) # -22 已绝迹
assert is_vetoed(2026, d, '入宅') for 受死日 in 入宅
```

> **铁案一句话**：没有比较级的「凶」，不能自己长出比较级。

## 6.14 论白虎朱雀下沉时辰

### 6.14.1 命题

**嫁娶的白虎/朱雀是「时辰级」凶神，不是「整日级」否决。旧实现整日否决，等于把 12 个时辰一起判死。**

### 6.14.2 典据与逻辑

- 白虎、朱雀在嫁娶语境中与「时辰」绑定（迎娶、发轿、进门各有其时辰）。
- 协纪嫁娶忌表以**月破、往亡**为日级；白虎/朱雀属黄道十二神，本为**时家**序列。
- 一日有 12 时辰，吉时凶时并存是常态；整日否决违背「择时」的本义。

### 6.14.3 软件处置（§212）

| 项 | 旧 | 新 |
| --- | --- | --- |
| 白虎 / 朱雀（嫁娶） | 整日 ⛔ 否决 | **时辰级**判定，红帖标注凶时 |
| 日级否决 | 有 | **撤除** |
| 红帖 | — | 时辰栏标「忌用」 |

### 6.14.4 反断言

```python
# 整日不得因白虎被否
assert not is_vetoed(day, '嫁娶') when only 白虎
# 对应时辰必须被标凶
assert hour_is_bad(白虎时)
```

> **铁案一句话**：时家的神，回到时辰里去；整日否决是维度的错。
