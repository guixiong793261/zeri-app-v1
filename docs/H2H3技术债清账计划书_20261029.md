# H2/H3 技术债清账计划书（测试基建统一 + 副本体系收敛）

> 日期：2026-10-29　　来源：`docs/全系统终极大考与全渠道发布验证报告_20261029.md` §三
> 拍板：用户批准三批按序开工；统一版仓**维持暂不收敛**，但须写入触发条件与标准动作，
> 并把"六副本"表述降级为 **3 内层 + 1 统一版仓**。

| 项 | 现状 |

| 统一入口 | **无**。逐个手工执行，靠脚本自身 print + 退出码判断 |
| pytest 基建 | **无**。无 `pytest.ini` / `conftest.py` / `pyproject.toml` 配置，主流 CI 无法直接识别 |

| 统一版仓 | `d:\自编择日软件\专业择日大师_统一版\专业级正五行择日软件_v1.0`：69 件 modules 中 **17 件漂移**，主程序 SHA 不同 |

## 二、概念收敛：从"六副本"到"3 内层 + 1 统一版仓"

| 旧表述 | 新表述 | 含义 |
| --- | --- | --- |
| 六副本（6 份 = 2 仓 × 3 层） | **3 内层**（主仓三层，必须逐字节一致） | 仓根 / 手机一键部署 / 模块完整版 |
| 同上 | **1 统一版仓**（快照仓，允许暂时漂移） | 统一版 v1.0，按触发条件整批收敛 |

标准校验口径：
- 日常改码 → 只校验 **3 内层** SHA 一致（`check_six_copies.py --main`，FAIL 应为 0）。
- 发布前 → 追加 **统一版仓** 对账（`check_six_copies.py` 不带参数 = 6 份），
  漂移清单逐个归因后方可收敛。
- 文档/commit 说明中不再使用"六副本必须一致"这一旧结论，改为上述分级口径。

## 三、第一批：统一 Runner（立即开工）

**交付物**：`tests/run_all.py`

**行为**
1. 自动发现 `tests/` 下 `verify_*.py` / `test_*.py` / `check_*.py`（可 `--pattern` 覆盖）。
2. 逐脚本以**子进程**执行（`sys.executable`，cwd=仓根，UTF-8 环境），捕获 stdout/stderr。
3. 单脚本超时（默认 300s）→ 记 `TIMEOUT`，不阻塞整批。
4. 输出三段：逐脚本 `PASS/FAIL/TIMEOUT exit=N 耗时`；失败脚本末 20 行输出；
   汇总 `TOTAL / PASS / FAIL / TIMEOUT`。
5. 退出码：全通过 0；任一失败 1；运行器自身异常 2。
6. `--json out.json` 输出机器可读结果（供 CI 与快照留档）。
7. `--filter 关键字` 只跑匹配脚本（调试期用）。

**验收标准**
- 124 脚本一遍跑完，`FAIL=0`（与当前逐个手跑结果一致）。
- 失败注入测试：人为改坏 1 个断言 → 运行器报 FAIL 且退出码 1，输出定位到脚本名。
- 运行总耗时与手跑同量级（不引入额外排盘重算）。

## 四、第二批：pytest 外壳（第一批验收后开工）

**交付物**：`pytest.ini`（或 `pyproject.toml` 段落）+ `tests/conftest.py` + `tests/test_runner_shell.py`

**行为**
- `conftest.py` 提供 `run_script(path)` fixture：子进程执行并返回 `(exit_code, stdout)`。
- `test_runner_shell.py` 用 `@pytest.mark.parametrize` 把 124 个脚本变成 124 个用例，
  断言 `exit_code == 0`；失败时把脚本输出挂到断言消息里。
- marker 分类：`@pytest.mark.verify` / `@pytest.mark.slow` 分离长跑脚本，便于 CI 分级。
- 不重写任何 verify 脚本逻辑（外壳只包装，不动断言），确保上/下两种入口结果绝对一致。

**验收标准**
- `pytest -q tests/test_runner_shell.py` 全绿；`pytest -m "not slow"` 子集全绿。
- 与 `tests/run_all.py` 结果逐脚本一致（比对 `--json`）。
- 能在标准 CI（GitHub Actions / GitLab CI）中以一条命令运行。

## 五、副本感知外扩（随第一批附带）

- 现状 4 个副本感知脚本 → 目标：**所有涉及主程序/评分器/贴类读数的脚本**
  在结论行追加 3 内层 SHA 断言（调用 `references/check_six_copies.py` 或其函数）。
- 实现方式：新增 `tests/_copy_guard.py` 小工具（返回三内层 SHA 是否一致），
  由各脚本按需 import；**不强制全量改造**，优先覆盖评分器/主程序/事项标准相关脚本。
- 验收：新增断言不会让现有脚本变红（当前三内层 SHA 一致）。

## 六、统一版仓：触发条件与标准动作（维持暂不收敛）

**触发条件（满足任一即启动收敛）**
1. 主仓连续 **3 批**无变更（以 001 记账批次为计数单位）；
2. 需要**对外发布**（打包/交付）前；
3. 累积未镜像文件达到 **100 件**。

**标准动作（快照式收敛，禁止零散镜像）**
1. 对账：`check_six_copies.py`（6 份）→ 导出漂移清单（当前 17 件）；
2. 归因：逐件判定漂移原因（本批改动 / 历史遗留 / 统一版专属改动），
   **统一版专属改动不得被覆盖**，须先回报用户；
3. 镜像：整批镜像主仓 → 统一版仓，不做单文件零散同步；
4. 验证：6 份 SHA 全一致 + `py_compile` 全量通过 + 统一版仓冒烟（启动 + 一次评分）；
5. 记账：001 新增条目记录镜像清单与 SHA；
6. commit：主仓与统一版仓分别独立 commit。

## 七、批次边界与停止点

| 批次 | 内容 | 停止点 |
| --- | --- | --- |
| 第一批 | `tests/run_all.py` + `_copy_guard.py` + 4→主要脚本副本断言 | 成稿即停，待拍板验收 |
| 第二批 | `pytest.ini` + `conftest.py` + `test_runner_shell.py` | 成稿即停，待拍板验收 |
| 收敛 | 仅在触发条件满足时启动 | 收敛前先呈报 17 件漂移归因 |

本计划书**只出方案，不改测试脚本、不动统一版仓**。
