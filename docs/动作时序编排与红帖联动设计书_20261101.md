## 〇、结论先行

1. **可做，且不需要新增任何评分/否决/神煞**。全部改动落在
   「纯函数调度层 + 展示层 + 字段传递 + 一次性接线」。
2. **不足三段的处置，建议「提示错峰，不降权」**（见 §四）：不剔除、不扣分、
   不改排序键，榜单顺序零漂移；仅用原因列 + 时间轴明示"缺哪一段、可怎么错峰"。
   §213 的 Q3「rank_day 插 action_tier」降为**可选第二档（默认关）**。
3. **一键生成红帖的链路是通的**，但须新增 5 个 entry 字段与 1 个回调；
   红帖侧只做三处加法，无 `action_plan` 时行为完全不变（向后兼容）。

   嫁娶红纱日已按 §212 剥离（分值表仍留惰性键）、发轿方向无采集入口。

## 三、动作时序模型

### 3.1 动作序列（配置化，禁止硬编码进判断逻辑）

```python
# modules/事项标准.py（新增纯配置区，不改 UI_EVENTS）
ACTION_SEQUENCES = {
    '嫁娶': [
        {'seq': 1, 'key': 'fa_jiao',  'label': '起轿·发轿', 'dir_required': True},
        {'seq': 2, 'key': 'ying_qu',  'label': '迎娶·进门', 'dir_required': False},
        {'seq': 3, 'key': 'jiao_bai', 'label': '交拜·合卺', 'dir_required': False},
    ],
    # 订婚/入宅/安葬按各自 _STAGE_LABELS 后续增补（P2-B 之后，不随本批）
}
```

- 文案唯一源 = 本表；`择日贴._STAGE_LABELS['marriage']` 改为**引用**此表，
  避免"反推写起轿、红帖写发轿"的两处漂移。
- 未配置的事项 → 动作轴整块不显示，红帖行为完全不变。

### 3.2 候选池与筛选规则

候选池 = 该日 `hours` 的 12 项。

| 规则 | 内容 | 依据 |
|---|---|---|
| R1 硬排除 | `disabled` / `veto > 0` / `score <= 0` / `shashi=True` | 时辰级既有判定 |
| R2 冲命 | 唯一源 = `disabled`（含冲新娘/新郎/阴胎/阳气）；plan 层再独立算一次年支+6 **仅作交叉校验**，不一致 → `warn` 显式提示，不静默 | 防 D3 双源 |
| R3 时序单调 | 按**钟点起点**排序，不按地支序（子时 23:00 应排最后） | 防 D2 |
| R4 一辰一动作 | 同一时辰不得分给两个动作 | 无典据支持同辰两礼 |
| R5 间隔不设硬限 | 三库无明文；仅提示"相邻两礼过近" | 不造规矩 |
| R6 子时 | **动作轴禁用**（见 Q6） | 23:00 子时日柱已换日，四柱与时辰不配套 |

### 3.3 选优算法（纯函数，无 GUI、无 IO）

```
plan_actions(hours, owners, actions) -> {
    'plan':    [{'seq','label','zhi','ganzhi','range','score','level','tags'}],
    'status':  'full' | 'partial' | 'insufficient' | 'none',
    'missing': ['起轿·发轿'],
    'checks':  [{'name':'cross_check','ok':True,'detail':...}],
    'alt':     [{'label':'起轿·发轿','suggest':'提前至卯时（若可）'}] # 错峰建议，仅文案
}
```

- 穷举 12 选 3 的递增组合（C(12,3)=220，含 2 段/1 段 <300 次），
  按 `(段数, Σscore, 起点)` 取最优；同分取**更早钟点**（民俗发轿宜早）。
- 单日 <1ms，不影响 30 天反推（现 2.9~6.6s）。
- **`alt` 只产出建议文案，绝不自动替换成凶时**。

### 3.4 状态分级

| status | 含义 | UI | 红帖 |
|---|---|---|---|
| `full` | 3 段齐 | 绿标三行 | 吉时区三段 + 等级 |
| `partial` | 2 段 | 黄标「缺 X」+ 错峰建议 | 两段 + `warn` 缺段行 |
| `insufficient` | 1 段 | 橙标「建议另择」 | 一段 + `warn` |
| `none` | 0 段 | 红标「本日无可用动作时辰」 | 不印动作轴，仅 `warn` |

## 四、不足三段：降权还是提示错峰？（用户问 1 的答复）

**建议：提示错峰为主，不降权。**

| 方案 | 做法 | 代价 | 结论 |
|---|---|---|---|
| A 降权 | `rank_day` 头部插 `action_tier`（full 0 / partial 1 / insuff 2 / none 3） | 改 Top-N 顺序，须重冻 `tests/verify_210_search_top_n.py` 基线；高分日被低分日挤下去，用户会质疑"为什么 90 分排在 82 分后面" | **默认关闭**，作为可选开关保留 |
| **B 提示错峰（推荐）** | 榜单顺序**完全不动**；原因列追加 `缺上轿吉时（2/3 段）`；tab3 给 `alt` 错峰文案 | 零漂移、零基线重冻；用户仍能看到"高分但动作受限" | **采纳** |

理由：

1. 用户心智是"高分日不该因为排不下三个礼就被踩下去"；剔出榜更会让人以为"软件没算到"。
2. 祥日挑时辰本是择日师的活，软件只做**可行性预警**，不做行政降级。
3. 降权一旦进排序键，每次动作轴口径调整都会连带漂移 Top-N，维护成本高于收益。

> **拍板项 Q2**：若你要求"榜单必须体现动作可行性强弱"，再启用 A 档（独立开关、
> 独立 commit、独立重冻基线），不与本批混提。

## 五、一键生成红纸帖

### 5.1 调用链（唯一路径，禁止反推模块自己开第二个红帖窗口）

```
反推 tab3「生成红纸帖」按钮
   │  当前选中日 + plan_actions 结果 + 用户在动作轴确认的时辰
   ▼
反推UI.on_send(entry)                       ← 新增回调（open_reverse_window 参数）
   ▼
主程序._receive_reverse_plan(entry)         ← 新增，唯一接线点
   ├─ 与 _zeri_tie_pending 同键 (date,event_type) 去重合并
   ├─ 择日贴窗口已开 → 前置并 add_entry；未开 → 暂存 + 打开
   ▼
择日贴 add_entry → prepare_entry → compose_detail_lines
   ├─ 硬否决 → compose_veto_lines
   ├─ 软忌   → compose_caution_lines
   └─ 正常   → compose_marriage_lines（① ② ③ + 缺段 warn）
```

### 5.3 红帖侧最小改动（三处加法）

1. `prepare_entry`：若 `entry['action_plan']` 存在 →
   `_jishi` 直接按 plan 生成（`manual=True, from_plan=True`），**跳过**自动前三筛选；
   仍执行 R2 交叉校验，冲突则**拒绝生成并弹窗说明**（绝不把冲命时辰印成吉时）。
2. `compose_marriage_lines`：`status != 'full'` 时在吉时区后追加
   `('warn', '⚠ 本日吉时不足：缺「起轿·发轿」，请另择或调整行程')`（tag 已注册）。
3. 打印模板：动作轴改用竖排编号 + `rule` 竖线（设计图 §4.3），属 **S5 增量**，可选。

### 5.4 与「三层四区」的对接位置

## 七、软忌 → 慎用帖（用户问 3 的答复 + 三处口径冲突）

### 7.1 现有分流（唯一事实源，不改）

```
_is_vetoed      = veto_reasons 非空  or  (score == 0 且 level 含凶)
_is_soft_caution = 非否决 且 level 含凶
```

- 硬否决 → `compose_veto_lines`（深红 +「不可使用」）
- 软忌 → `compose_caution_lines`（深红 +「本日多煞 建议慎用」+ 时辰不印等级）
- 其余 → 模板吉帖 + `_degrade_warn_lines` 动态软忌警示块

### 7.2 事实纠偏（§213 已过时）

| 旧说法 | 2026-11-01 现状 |
|---|---|
| "红纱日降级 -20"是嫁娶典型软忌 | 嫁娶**专用**的 `('嫁娶','红纱日') = -20` 发射已按 §212 删除（协纪 p279217 明斥「甚属无当」）；**但基类「红砂日 -15」仍在全事项发射**（[神煞基类.py](file:///d:/自编择日软件/专业级正五行择日软件/modules/shensha/神煞基类.py#L1939-L1940)、[通用神煞.py](file:///d:/自编择日软件/专业级正五行择日软件/modules/shensha/通用神煞.py#L543-L544)），经别名归一同为「红纱日」。故**嫁娶仍会命中 -15 软忌（扣分不否决）**，量级由 -20 改为 -15 |
| — | 当前现实软忌来源：① 红砂日 -15（全事项）；② 评分 `reason` 的「忌：」段（受死/鬼哭/黄沙等）；③ `level` 含凶 |

### 7.3 冲突 1：反推"慎用" ≠ 红帖"慎用帖"

| | 判据 |
|---|---|
| 反推 `classify_day` | `慎用` = 负分总和 ≤ -20（**等级可能仍是吉**，如 85 分扣 20 → 标黄） |
| 红帖 `_is_soft_caution` | 非否决且**等级含凶**（如 33 分 ❌凶） |

→ 同一日：反推可能标"慎用"黄格，红帖却印**白底吉帖**。用户会认为"两处不一致"。

**建议（Q5）**：红帖分流**仍以等级为唯一源**（不改既有行为、不影响手动加入的日课），
仅在吉帖警示区追加一行事实：
`注意事项：反推标记本日为「慎用」（神煞负分合计 -X），宜酌情避用`
—— 一句话消解错位，且零分流改动。

### 7.4 冲突 2：动作轴时辰的"动态软忌"

若 `plan` 某段所在时辰命中凶煞（`凶` 列表非空或负分），红帖该段**只印时柱+时段，
不印等级**（复用慎用帖的"多煞之日时辰不得称吉"口径）；整日 `_is_soft_caution`
时，三段一律不印等级，标题改「慎用」。
→ 这是"动态软忌"的最小落地：**不新增判定，只降印刷口径**。

### 7.5 冲突 3：分值表惰性键

`('嫁娶','红纱日') = -20` 仍在分值表但发射端已删。**本批不动**（属分值表清理，
须独立批次 + 三库复核），仅在本书登记，避免未来误以为是活键。
