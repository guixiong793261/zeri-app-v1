## 二、Q1｜事主4 出生日期／四柱"丢失"

### 2.1 结论

**不是前端漏传，也不是后端 `continue` 跳过导致数据丢失；数据本就不存在。**
真实机制是：**未填写日期的事主卡片，其姓名默认值 = 角色名（恒非空），详情窗口据此打印标题；随后空日期触发 `int('')` 异常，被裸 `except: pass` 静默吞掉，明细区整体空白。**

## 三、Q2｜年命相冲为何在相主得分里 0 扣分

### 3.1 结论（三层）

**① 口径澄清（重要）**：本例「日课年支**丑** 冲 事主年命**未**」**不属于**档1 硬否决。
- 现行三档口径：档1 = 年命 × **日课日支** 六冲 → -30 硬否决；档2 = 年命 × 月支/时支 → -15/-10；流年档 = 年命 × **日课年支** → -15 不否决。
- 本例日课**日支申** × 未 → 不冲；月支辰／时支午 × 未 → 不冲（午未六合）。唯一冲突是**年支丑 × 未** → 命中**流年冲太岁档（-15，不否决）**。
- 因此「往往需要重扣甚至一票否决」在本例**不成立**——它按现行口径就只是 -15。真正的一票否决档（年命×日支）本例未触发。

**② 漏判根因**：流年档在 GUI 真实路径（`birth_date`）下被显式排除。
[评分器.py#L5316-L5325](file:///d:/自编择日软件/专业级正五行择日软件/modules/评分器.py#L5316-L5325)：

```python
if not owner_year_zhi and owner.get('birth_date') and \
        _is_wangming_role(owner.get('role', '')):
    # 仅仙命需要 birth_date 解析（冲太岁硬否决）。
    # 普通事主保持旧口径：只认 sizhu/生肖 键，不在此扩展，
    # 避免激活历史死档漂移锁定基线（2021金课 事主4 未冲丑）。
```

注释**自证**：该限定正是为了锁住「2021 金课 事主4 未冲丑」这条历史基线——即本轮用户报告的这一课。修造无仙命，`_is_wangming_role` 恒 False → 修造普通事主**永远走不到流年档**。

**③ 第三套通道完全死锁**：修造神煞层的"年冲/月冲/日冲/时冲"本应发 -25/-15/-35/-12。
[修造神煞.py#L342-L349](file:///d:/自编择日软件/专业级正五行择日软件/modules/shensha/修造神煞.py#L342-L349)：

```python
owner_zodiac   = owner.get('生肖', '')
owner_year_zhi = owner.get('年支', '')
owner_name     = owner.get('姓名', f'事主{i+1}')
if not owner_zodiac and not owner_year_zhi:
    continue
```

GUI 批量扫描路径的 owner **没有** `生肖`/`年支`/`姓名` 键（见 §2.3）→ 两个取值均为空 → `continue` → **整条通道 0 发射**。
本例本应命中：**年冲事主4（丑未冲）-25**、**时合事主4（午未六合）+6** —— 两者都没出现。

### 3.2 三套通道口径分裂矩阵（本例实测）

| 通道 | 认什么键 | GUI 路径是否生效 | 本例应得 | 本例实得 |
|---|---|---|---|---|
| 修造神煞 `_check_special_shensha` | `生肖`／`年支`／`姓名` | ❌ 全死 | 年冲 -25、时合 +6 | **0 / 0** |
| 评分器 相主档1/档2 | `sizhu` → `生肖` → `birth_date` 兜底（[L5172-L5186](file:///d:/自编择日软件/专业级正五行择日软件/modules/评分器.py#L5172-L5186)） | ✅ 生效 | 档1 不冲、档2 不冲 → 0；伏吟 +3 | **+3 ✅** |
| 评分器 流年冲太岁档 | `sizhu`／`生肖`；`birth_date` **仅仙命**（L5316） | ❌ 普通事主跳过 | -15 | **0 ❌** |
| 修造规则 `_check_po_and_sili` | `_get_owner_year_zhi` **支持 birth_date**（[修造规则.py#L337-L343](file:///d:/自编择日软件/专业级正五行择日软件/modules/rules/修造规则.py#L337-L343) + [L214-L227](file:///d:/自编择日软件/专业级正五行择日软件/modules/rules/修造规则.py#L214-L227)） | ✅ 生效 | 忌项 → 忌事 -15 | **-15 ✅（唯一落账通道）** |

> 结论：**同一条「年命冲」信息，在修造里存在 3 套互不相认的实现；GUI 路径下只有"规则层忌项 -15"这一条活着。** 相主得分显示 0 是真的，但总分并非完全没扣（-15 在忌事里）。

### 3.3 与签手机制一致的对照

嫁娶／出行／开业／安床／作灶 的 `_check_special_shensha` 均为同款"年冲/月冲/日冲/时冲"（[出行神煞 L282-L299](file:///d:/自编择日软件/专业级正五行择日软件/modules/shensha/出行神煞.py#L282-L299)、[开业神煞 L252-L269](file:///d:/自编择日软件/专业级正五行择日软件/modules/shensha/开业神煞.py#L252-L269) 等），**键名同款、同样只认中文键**。所以这不是修造独有，是**批量扫描路径的 owner 结构与神煞特殊通道契约不匹配的全局问题**（本批只登记，不扩面）。

### 3.4 影响面（待修复批量化）

- 若接通流年档（birth_date 普通事主）：修造/动土/拆舍等"事主中心"事项在流年冲太岁时统一 -15/人，**会普遍改变历史基线**，必须全年对拍（2019-2030）后重冻。

### 5.4 与用户报告 -100 / -60 的差异解释（机制一致，项集不同）

用户报告中「底层硬扣 -100（三煞）／五行忌事 -60」，与实测 -150 / -105 **不是矛盾，而是同一机制在不同时柱下的两套项集**：

- 因此 -100 与 -150、-60 与 -105 均为**同一双计公式的不同输入**；100 : 60 与 150 : 105 不成固定比例，正好说明是"项集增删"而非"统一系数"。
