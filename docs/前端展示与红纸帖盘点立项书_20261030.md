## 一、红纸帖 / 发轿单结构盘查

### 1.1 整体结构：吉日分支 vs 否决分支

红纸帖（日课单）的渲染入口为 [择日贴.py](file:///d:/自编择日软件/专业级正五行择日软件/modules/择日贴.py) 中的 `compose_detail_lines(e)`（[L900](file:///d:/自编择日软件/专业级正五行择日软件/modules/择日贴.py#L900)）。

**核心分派逻辑**（[L904-L920](file:///d:/自编择日软件/专业级正五行择日软件/modules/择日贴.py#L900-L920)）：

```
compose_detail_lines(e):
  if e['_is_vetoed']:
      return compose_veto_lines(e)        # 否决硬分支
  t = e['_template']   # marriage/engagement/xiuzao/dongtu/ruzhai/anzhang/common
  → 按模板分派到 6 类专版 compose_*_lines
  → 其余 → _compose_common_detail_lines   # 红纸通用
```

**否决判定**在 `prepare_entry`（[L329-L343](file:///d:/自编择日软件/专业级正五行择日软件/modules/择日贴.py#L329-L343)）：
- 优先取 `entry['veto_reasons']`（主程序从评分结果 `detail` 透传，见 [主程序.py L8481-L8493](file:///d:/自编择日软件/专业级正五行择日软件/主程序.py#L8481-L8493)）；
- 兜底：`score == 0` 且 `level` 含「凶」字 → 同样视为否决。

| 维度 | 吉日分支（`compose_*_lines`） | 否决分支（`compose_veto_lines`，[L864](file:///d:/自编择日软件/专业级正五行择日软件/modules/择日贴.py#L864)） |

### 1.2 关键否决原因在帖纸上的排版

关键否决原因（受死日、冲新娘/冲事主、红纱日降级、重丧日、三煞犯山向等）在红纸帖上**不做分项专门排版**，统一走两条通道：

**通道 A：否决日 → `compose_veto_lines` 的【否决原因】段**（[L886-L892](file:///d:/自编择日软件/专业级正五行择日软件/modules/择日贴.py#L886-L892)）

- 样式：`body` 级（楷体 16pt，红纸黑字），每行前缀 `⚠ `；
- 在屏幕预览（`_fill_text`，[L1471-L1484](file:///d:/自编择日软件/专业级正五行择日软件/modules/择日贴.py#L1471-L1484)）中，凡含 `⚠` 的行自动套 `warnhl` 标签 → **黄底黑字**（[L1406](file:///d:/自编择日软件/专业级正五行择日软件/modules/择日贴.py#L1406)），相对醒目；

**通道 B：安葬吉日的【重要避忌】段**（`compose_anzhang_lines`，[L835-L852](file:///d:/自编择日软件/专业级正五行择日软件/modules/择日贴.py#L835-L852)）
- 原写死「复日/年重丧/三丧日均已避开」属造假，已改为动态渲染：
  - 先列本课真实 `veto_reasons`（`⚠ {原因}`，[L840-L843](file:///d:/自编择日软件/专业级正五行择日软件/modules/择日贴.py#L840-L843)）；
  - 无致命大凶时明示「无明显致命大凶」（[L845](file:///d:/自编择日软件/专业级正五行择日软件/modules/择日贴.py#L845)）；

## 二、输入动线遗留点

### 2.1 入宅的多事主输入

**现状**：入宅事项的事主录入界面在 `update_owners_frame`（[主程序.py L1417](file:///d:/自编择日软件/专业级正五行择日软件/主程序.py#L1417)）中按事项类型确定事主卡片：

```python
# L1485-L1486
elif event_type in ["修造", "动土", "拆舍", "入宅", "开业", "出行"]:
    owners = ["事主1", "事主2", "事主3", "事主4"]
```

→ 入宅**支持 4 个事主卡片**（事主1~事主4），与修造/动土等共用同一套 4 卡布局。

**生肖录入设计**：生肖**非直接输入字段**，而是由出生日期计算四柱后自动派生。每张事主卡片的四柱行显示「生肖」标签（[L1600-L1604](file:///d:/自编择日软件/专业级正五行择日软件/主程序.py#L1600-L1604)），点击「计算四柱」按钮后由 `calculate_owner_sizhu`（[L2578](file:///d:/自编择日软件/专业级正五行择日软件/主程序.py#L2578)）算出年支，查 `SHENGXIAO_MAP` 填入 `zodiac_var`（[L2640-L2646](file:///d:/自编择日软件/专业级正五行择日软件/主程序.py#L2640-L2646)）。

**生肖透传到评分**：在 `start_calculation`（[L3977-L3992](file:///d:/自编择日软件/专业级正五行择日软件/主程序.py#L3977-L3992)）中，每个事主的 `owner_data` 含 `'生肖': year_zhi`（年支字符），供「避刑冲害事主生肖」条件过滤（[L4604-L4616](file:///d:/自编择日软件/专业级正五行择日软件/主程序.py#L4604-L4616)）与评分器相主匹配使用。

**「半权不否决」问题现状**：该问题的根因是 GUI 无生肖直接输入、须靠出生日期计算。当前界面已通过「计算四柱」按钮自动派生生肖并透传，**但存在两个遗留**：
1. **未点「计算四柱」的事主**：`year_zhi` 为空 → `生肖` 键为空字符串 → 避冲克条件与相主匹配均失效。代码无强制要求用户必须点计算按钮，也无「未计算四柱」红色警示；
2. **未填出生日期的事主**（如只填了事主4姓名）：在 `start_calculation` 中被 `except (ValueError, TypeError): pass` 静默跳过（[L4005-L4006](file:///d:/自编择日软件/专业级正五行择日软件/主程序.py#L4005-L4006)），不进入 `owners_data`，自然不参与计分——与「修造事主4」同根。

### 2.2 修造的事主4（缺四柱不参与计分）

**现状**：修造/动土/拆舍与入宅同样使用 4 卡布局（[L1486](file:///d:/自编择日软件/专业级正五行择日软件/主程序.py#L1486)）。用户若只填前 3 人事主信息、第 4 张卡留空（姓名默认「事主4」），则：

- **评分阶段**：`start_calculation` 遍历 `self.owners_info` 时，空卡因 `year` 为空触发 `ValueError`，被 `except` 静默跳过（[L4005-L4006](file:///d:/自编择日软件/专业级正五行择日软件/主程序.py#L4005-L4006)），不进入 `owners_data` → **不参与计分**；
- **详情展示阶段**：在日课详情的【事主信息】段（[L5662-L5691](file:///d:/自编择日软件/专业级正五行择日软件/主程序.py#L5662-L5691)），§187 Q1 已修复：未填出生日期的事主显式标识 `未提供出生日期（不参与相主计算）`（[L5690-L5691](file:///d:/自编择日软件/专业级正五行择日软件/主程序.py#L5690-L5691)），不再让空日期 `int('')` 抛 `ValueError` 后被裸 `except` 静默吞掉；
- **提示方式**：仅在日课详情文本中以普通正文（`text.insert`，无特殊颜色/字号）提示「未提供出生日期（不参与相主计算）」。

**问题**：提示信息藏在详情窗口中段的【事主信息】段内，无颜色高亮、无弹窗、无主界面警示。用户在择日结果列表或择日贴中完全看不到「事主4未参与计分」的提示，容易误以为 4 位事主都参与了评分。

## 三、高警示 UI 盘点

### 3.1 未填山向的红字警示块

**位置**：日课详情窗口（双击结果树某行触发）的**最顶部**。

**代码定位**：
- 警示内容来源：[评分器.py L2875-L2890](file:///d:/自编择日软件/专业级正五行择日软件/modules/评分器.py#L2875-L2890)。§190 C2 / §199 P2（2026-10-29 扩面）：凡山向类事项（修造/动土/拆舍/安葬/作灶/安床/开业等，出行除外）未填 `shan_xiang` 时，`warnings` 列表追加 `'⚠ 未提供山向，无法评估方位吉凶，请勿盲目使用'`，并作为评分结果 `warnings` 字段返回。
- 警示渲染：[主程序.py L7497-L7518](file:///d:/自编择日软件/专业级正五行择日软件/主程序.py#L7497-L7518)。从 `detail.get('warnings')` 取出后，在全文 `content` 追加完成后，于 `"1.0"` 位置**前插**警示块，再用 `red_warn` 标签整行打标。
- 标签样式定义：[主程序.py L5483-L5485](file:///d:/自编择日软件/专业级正五行择日软件/主程序.py#L5483-L5485)。

**视觉效果**：

| 属性 | 值 |
|---|---|
| 颜色 | `foreground="#FF0000"`（纯红） |
| 字号 | 微软雅黑 13pt bold（与详情正文 `_BASE_FONT = 微软雅黑 13` 同级，但加粗） |
| 位置 | 详情窗口第 1 行（真置顶，`1.0` 前插） |
| 内容格式 | `【⚠ 重要警示】\n{各条 warning}\n━━━━━━…（分隔线）\n\n` |
| 背景 | 无背景色（仅红字） |

**醒目度评估**：
- **优点**：真置顶（§191 已修复原「落在中段」的 bug），纯红加粗，分隔线清晰；
- **不足**：
  1. 字号仅 13pt，与正文同级，靠颜色和加粗区分，**视觉震撼度不足**——在 760×680 的详情窗口中，红色一行容易被下方大段黑色正文「淹没」；
  2. 无背景色块/边框/图标放大，仅靠 `foreground` 红字，在高对比度屏幕上不够「警示」；
  3. 该警示**仅出现在双击打开的日课详情窗口中**，结果列表、择日贴、打印件均无对应山向缺失警示；
  4. 评分器层面山向缺失时方位通道静默跳过、分数虚高，仅靠详情窗口一行红字提示，用户在结果列表中选日时看不到。

## 五、改进建议

### 红纸帖视觉跃升
1. **否决日红纸帖改为「警示底」**：红纸底不变，但标题「本日不吉」加大至 42pt+、加 `✕` 大符号、正文否决原因段用**黄底黑字加粗**（现有 `warnhl` 可复用，但需加大字号）；
2. **吉日分支统一补【重要避忌】段**：参照安葬模板（[L835](file:///d:/自编择日软件/专业级正五行择日软件/modules/择日贴.py#L835)），为修造/动土/入宅/嫁娶/通用模板各加一段动态避忌，列出本课 `veto_reasons`（硬否决已走否决分支不会到这里，故此处列「软降级」项：红纱日降级、受死日扣分、重丧日临、冲辅助者等）+ 复日类实测命中；
3. **冲新娘/冲事主显式标注**：嫁娶帖在乾造/坤造行或冲煞行后补「⚠ 日支冲{新郎/新娘}年支，已扣分/已否决」；入宅帖合家成员已有冲克标注（[L764](file:///d:/自编择日软件/专业级正五行择日软件/modules/择日贴.py#L764)），可推广到修造福主行。

### 高警示 UI
4. **结果列表否决日行红色标识**：`_star_row_tag` 增加对 `❌`/`凶` 的判定，返回如 `veto` 标签，`tag_configure('veto', background='#FFE0E0', foreground='#C00000')`；
5. **详情【一票否决】段红色高亮**：该段整段套红底/红字标签，或至少否决原因行前缀 `✗` 并染红（现有 `red_cross` 标签可复用）；
6. **未填山向警示强化**：字号提到 16pt+、加红底白字/黄底黑字背景块、加边框；并扩展到结果列表（山向缺失的日课在某列标红「⚠ 无山向」）和择日贴（在红纸帖标题下加一行黄底警示）；
7. **否决日加入择日贴二次确认**：若 `veto_reasons` 非空，弹 `askyesno` 警示「该日为否决日，确定加入择日贴？」。

### 输入动线
8. **「未计算四柱」红色警示**：事主卡片若填了姓名但未点「计算四柱」，在卡片上加红字提示「⚠ 未计算四柱，不参与相主/避冲克」；
9. **空卡事主主界面提示**：择日完成后，若有空卡事主未参与计分，在结果区上方加一条横幅提示「事主4 未提供出生日期，未参与计分」；
10. **嫁娶/安葬八字强校验**：嫁娶至少要求新郎+新娘双方出生日期（非强制但强烈警示）；安葬要求死者出生日期（仙命），缺失时弹警示。

## 六、风险评估

| 风险 | 说明 | 缓解措施 |
|---|---|---|
| 红纸帖模板改动面广 | 6 类专版 + 通用 + 否决 + 总录，加【重要避忌】段需逐个模板插入，易漏改 | 在 `compose_detail_lines` 入口统一注入避忌段（独立函数），避免逐个模板改 |
| 否决判定口径变化风险 | 若在评分器层补「软降级」列表，需确保不改变现有 `veto_reasons` 硬否决口径 | 新增独立字段如 `soft_warnings`，不碰 `veto_reasons` |
| 结果列表红色标识可能「过于刺眼」 | 否决日占比可能较高（嫁娶 93.7% 判凶），全红背景可能影响扫表体验 | 用淡红底（#FFE0E0）+ 红字，不用深红底；或仅「等级」列单元格标红 |
| 强校验可能打断用户习惯 | 嫁娶/安葬八字强校验弹窗可能让习惯快速扫日的用户反感 | 改为「软警示」（横幅/红字）而非 `showwarning` 阻塞弹窗，保留「仍要继续」选项 |
| 打印 HTML 与屏幕预览样式不一致 | `warnhl` 在屏幕 Text 和打印 HTML 中均有定义，但字号/行高不同 | 改动时同步核对 `_PRINT_TEMPLATE` 与 `tag_configure` 两处 |
